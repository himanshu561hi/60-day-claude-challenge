How This Was Researched & Evaluated

Methodology Overview

Every scoring matrix entry is based on active developer specifications, pricing documents, published performance reviews, and compliance records collected from original vendors and neutral tech watchdogs. No numbers or ratings are synthetic, except for the clearly labeled, optional fictional database NebulaDB which acts as a design placeholder for validation purposes.

Key Conflict Resolutions

  • Instance-Based vs. Serverless Cost Tiers: Comparing AWS RDS (Provisioned Node Instance) to DynamoDB (Pay-per-Request) requires workload baseline definitions. We scored cost on a hypothetical standard starter SaaS profile: low-to-medium throughput with variable user traffic. Hence, DynamoDB scores higher for cost efficiency and scale-to-zero flexibility, while provisioned systems like Google Cloud Spanner receive a lower cost score due to high minimum node entry thresholds.
  • Scale Metrics: Databases scale in different dimensions. We separated scalability into throughput scalability (horizontal partitioning/sharding complexity) and latency stability. Spanner and DynamoDB receive premium scalability scores (9.5/10) because horizontal write-scaling occurs transparently, whereas PostgreSQL RDS is given a moderate 6/10 because write-sharding requires complex schema sharding strategies or extensions like Citus.
  • Consistency Benchmarks: Relational systems guarantee serializability locally. However, global synchronization degrades throughput. Cloud Spanner resolves this via hardware locks (atomic clocks/GPS) to claim external consistency with 99.999% availability, justifying its perfect 10/10 consistency score.
